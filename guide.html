02No metadata, so it gets researched

Netflix and Prime's own history pages disclose a title and a date; nothing else. Every genre tag and cast credit across the full watch-history record was independently sourced through per-title research, not inferred from platform metadata. Watch status is likewise inferred from episode counts and gaps, never presented as scraped fact.

Coming Soon draws only from named, verifiable sources: BritBox, PBS Masterpiece, Netflix Tudum, Den of Geek, What's on Netflix, and JustWatch, cited so each claim's reliability can be judged independently. Where verified art doesn't exist, the record says so by leaving the space empty, rather than substituting a guess that looks like it might be real.

03Signature genres in full, generic at a third

Broad categories (Comedy, Drama) are shared across too many unrelated titles to constitute meaningful evidence on their own. Genres with real recurrence in your own history (British Procedural, Spy Thriller, Mystery, Action Thriller) are weighted in full, with an added signal for cast overlap against titles you've already valued. A genre you've explicitly rejected is capped regardless of any other data pointing the other way: expressed preference overrides inferred pattern.

Full weight

British Procedural, Spy Thriller, Mystery, Action Thriller: genres with real recurrence in your own watch history, plus cast-overlap bonus.

Capped, regardless of score

Sci-fi, fantasy, rom-com: explicitly rejected. A high score elsewhere can't override a genre you've already ruled out.

04A snapshot, not a live connection

This reads from a single published snapshot rather than a live session; nothing touches your Netflix or Prime account while you're using it. Synchronization happens deliberately, in a Cowork session, either at your request or on a fixed Monday schedule, and only then is the static record rebuilt.

05Publishing changes automatically

Every change publishes to the live site automatically, with no manual deploy step. That's what made it possible to add the first fully live feature: removing a title now updates every device immediately, not just the one you dismissed it on.

06What's still manual

Removing a title syncs everywhere instantly. As of 2026-08-16, keeping it off next week's rebuilt list no longer takes a message to anyone: a weekly GitHub Actions job compares what's been dismissed live against the permanent exclusion list, fixes any gap itself, and opens a pull request for Susan to merge — the fix is fully automatic, only the merge is manual. As of 2026-08-17 the ✓ button works the same way: marking something already seen records it permanently and takes its row off the page, both done by GitHub Actions, so nothing you have already watched can come back in next week's list. What's still genuinely manual is the other button: marking something "currently watching" syncs live instantly, but turning that into a permanent entry (so it survives a rebuild and keeps its poster art) still needs a person's judgment call, since a good entry needs real artwork and accurate progress text, not just a diff-and-append. A weekly job flags when that's missing rather than guessing at it. A scheduled health check (added 2026-08-14) also runs weekly and confirms the live site loads and both Functions are working, plus that every Currently Watching row has real artwork — but it checks that the site is healthy in general, not that any one specific change actually published, so checking the live site by eye after a real update is still worth doing. Two more gaps closed on 2026-08-17. Your watching and dismissed flags used to exist only inside Netlify with no copy anywhere; a weekly job now saves them into the repository and opens a pull request to merge. And every push is now checked for titles that would show a plain monogram instead of real artwork, across the whole page rather than one section, after four separate rounds of missing posters being spotted by eye first. Three more checks were added the same day, each one aimed at something that had already gone wrong: a pick can no longer be something already in the watch log, a row can no longer survive for a title that was removed, and a list that collapses into a single genre fails outright.

Build your own · a starting point

Copy this prompt to start

This entire site (the recommendation logic, the dashboard, the domain, the self-updating schedule) started from a single written request to Claude. It was built in stages, in conversation, with every irreversible step (spending money, publishing, connecting accounts) held for explicit approval along the way. Below is a version of that starting request. Copy it, adapt it to your own topic, and paste it into a new Claude conversation.

I want to build a small personal recommendation site for [your topic, e.g. books I've read, restaurants I've tried, podcasts, wine, whatever you actually track].

Here's the pattern I want it to follow:
1. Pull my real history from wherever it already lives (an account, a spreadsheet, an app). I don't want to re-enter anything by hand.
2. Rank new candidates against what I've actually liked before, not a generic popularity or trending list.
3. Publish it as a small, real website I can bookmark and check from my phone. No login needed for me to view it day to day.
4. Let me dismiss things I'm not interested in with one click, and have that stick permanently.
5. Refresh itself on a schedule, so it stays current without me having to ask every time.
6. Be honest in the interface about what's automatic versus what still needs me. Never invent or guess at data it can't verify.

Please help me scope this into a first small version we can finish today, tell me exactly what you'd need from me at each step (any account access, any purchase like a domain name, anything you can't do without my say-so), and don't do anything irreversible without checking with me first.

Swap the bracketed topic for your own, or hand it to Claude exactly as written and answer its follow-up questions. Either works.

What it takes on your end

  • A Claude account with access to Cowork (or Claude Code, for a more technical, terminal-based version of the same idea).
  • A few short check-ins over the following days or weeks. This kind of project improves in passes, not one sitting.
  • A willingness to say yes or no when Claude asks. It will hold at anything with a real-world consequence rather than guess.

Field notes

What we'd tell you before you start

A better formula can't fix a bad starting list. An early version ranked movies from a generic "trending now" list: the same list every visitor to a streaming site sees. A slapstick comedy nearly outscored a spy thriller starring Rami Malek, because both titles came from that same undifferentiated pool and every genre was weighted equally. The fix wasn't a smarter formula. It was pulling candidates only from Susan's own multi-year watch history instead. No amount of scoring sophistication rescues a candidate list that isn't personalized to begin with.

Claude asks before it spends, every time, no exceptions. Registering this site's domain name is the clearest example: before buying streamingscout.org, Claude confirmed the exact domain and the $10.49 price with Susan, and would not complete the purchase without her card on file and her explicit go-ahead. That's not a one-time courtesy. It's the standing rule applied to every dollar this system touches.
