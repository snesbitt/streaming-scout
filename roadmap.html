Roadmap · built in deliberate phases

Six phases live. Four to go.

The plugin, the dashboard, the domain, scheduled resync, this month's content refresh and the backend are all done. Catching the account list up to reality is underway. What's next is listed honestly below.

1

The plugin

Live

Recommendations built from what you actually watched

Five Cowork skills read your Netflix and Prime Video history straight from the browser, tag genre and cast through web research, and score every candidate against a taste profile built from real, multi-year viewing. Broad genres count for about a third of a title's score; genres you've shown you love count in full, with a bonus when the cast overlaps a show you finished and loved. The Coming Soon feed draws on BritBox, PBS Masterpiece, Den of Geek, and Netflix Tudum.

2

The snapshot dashboard

Live

A page you can open on a phone

A static site with the latest Top Picks, Taste Profile, and Coming Soon feed, rebuilt to the shared house style: Lora, cream shell, the same wordmark family as the other sites. Installable to the Home Screen, meets WCAG AA contrast, and every poster and control has a fallback so nothing shows up broken.

3

A real domain

Live

One address, not a netlify.app subdomain

streamingscout.org, registered through Netlify's own domain search and connected as the project's primary domain. DNS and the HTTPS certificate provision automatically.

4

Scheduled resync

Live

Stays current without being asked

A Monday-morning task resyncs your watch history and rebuilds Top Picks and Coming Soon on its own, honoring your exclusion list and stopping rather than publishing a partial result if a step fails. Persistent data now lives in this repo's data folder, after an earlier version pointed at a folder that vanished between runs and cost most of the watch history. Susan still runs the push that publishes it.

8

Content refresh & 2026 polish

Live

Grounded in the whole history

A full resync onto the complete 919-title, 2010–2026 log, Top Picks rebuilt across six distinct veins with a real actor list instead of one repeated genre, and Currently Watching and Coming Soon caught up to what's actually airing. Fonts are now self-hosted and posters lazy-load below the fold, for a faster page.

6

A real backend

Live

Infrastructure that matches the polish, and GitHub doing more of the upkeep itself

Netlify Functions on a GitHub repo that redeploys itself on push. Dismiss and status are both live, bounded, and Blobs-backed, so hiding a title or flagging it as watching/watched syncs across devices instantly. As of 2026-08-14 a scheduled health check (scripts/smoke.mjs) confirms the live site is actually up and both Functions are reachable and validating input. As of 2026-08-16, GitHub Actions took on real ongoing upkeep, not just checks: a weekly job now diffs the live dismiss store against the exclusion file and opens its own pull request to fix any gap, using GitHub's own bot identity, not a person or a Claude session; a second weekly job flags (but doesn't auto-fix) any "currently watching" title missing its permanent on-page entry; and the smoke check now also confirms every Currently Watching row has real poster art, not just a placeholder. The weekly artwork-sourcing sweep still runs as a Claude session (finding and judging real key art isn't mechanical), but now lands its work on a reviewable branch with a ready pull-request link instead of asking for a blind push. As of 2026-08-17 the last item here, automated backups, is closed too, and closed against the hole that was actually open. The data folder has been version-controlled since July, so every past version is already recoverable; what it lacked was anything that would notice a truncation, and a check now fails the build if any data file is emptied, deleted or sharply shrunk without that being recorded on purpose. Separately, the watching and dismissed records held by the live site existed only inside Netlify with no backup at all, and a weekly job now snapshots them into the repo and opens its own pull request, refusing to overwrite a good snapshot with a smaller or empty one. Also as of 2026-08-17, every push is checked for title rows that would render without real poster art, after four separate rounds of gaps being spotted by eye on the live page instead. Later the same day the checks got sharper still, each one aimed at a mistake that had actually happened rather than an imagined one: nothing can be recommended that is already in the watch log (a rebuild had offered back a show finished five weeks earlier), no row can survive for a title already removed (seven were found still shipping, two of them nineteen days old), and a list that collapses into one genre fails the build. Both Functions were also rewritten to store one record per title instead of rewriting a single shared list, which had been quietly discarding one of any two changes made within a few seconds of each other. And the loop finally closes on its own: removing a title, or marking it already seen, is now recorded and taken off the page by GitHub Actions, which opens a pull request for review rather than waiting for anyone to remember.

5

Browse the full watch log

Future

See the evidence, not just the answer

A searchable view of the full logged watch history, filterable by service, genre, or actor, so you can see what's behind a recommendation.

7

Protect saved changes

Future

A shared link can't quietly change what's recommended

Dismissing a title is open to anyone with the link today, since a "not interested" flag felt low-stakes at first. This gates it behind the same shared edit key Vinyl Scout's catalog uses, remembered per device so it doesn't cost a retype every visit. Browsing stays open to anyone.

9

A real scoring formula

Future

A score you could re-add by hand

Every match percentage today comes from Claude applying the same documented weighting rules fresh each rebuild. This turns that into a literal stored formula: fixed weights per genre and actor, one small function that combines them, the same shape Travel Intelligence uses for flight scoring. Judging what genre a brand-new title even is stays a judgment call, not a lookup.

10

Catch the account list up to reality

In progress

The tracked-services list stopped matching what's actually watched

Started as an audit after Currently Watching outgrew the four services the About page and Coming Soon skill knew about. Done: MGM+ and Paramount+ confirmed as real subscriptions and promoted to reviewed, badged services; the tracked-services stat and STREAMING_PROFILE.md corrected to 7 (2026-08-06), with an automated content-drift check now guarding that number against silently going stale again (2026-08-08). Closed 2026-08-16: MGM+ and Paramount+ now have named, per-service Coming Soon sources, the last real gap here. MGM+ press turned out to live inside the Amazon MGM Studios press site rather than a standalone MGM+ domain, which is why earlier passes missed it; Paramount+ has a proper chronological release feed at Paramount Press Express. Every one of the seven tracked services now has its best source written down in STREAMING_PROFILE.md. An earlier pass that day reported BritBox and Hulu as having none; both were wrong, and Susan supplied the real pages. BritBox's lives at a URL with an underscore, and the hyphenated spelling returns a 404, which is the likeliest reason it was missed. Still open: Nat Geo and Hulu stay intentionally off the tracked list (both handled instead through off-platform logging and the always-checked candidate policy, since neither has a syncable account page), which is a real design decision, not an oversight, but is worth documenting here plainly rather than leaving as implicit.
